# Laporan Perbaikan BUG-004

## Langkah 1 — Konfirmasi dan Batas Masalah
**Gejala**: UI terkadang menimpa hasil request yang baru dengan hasil request lama jika terjadi pembatalan permintaan (abort) secara beruntun.
**Tahap**: `api.js` fungsi `doFetch` pada blok `finally`.
**Batas**: Hanya muncul ketika ada dua request atau lebih dipanggil dalam waktu cepat; Request lama yang dibatalkan sempat mencapai blok `finally` dan menghapus `activeController` yang sudah dialokasikan untuk Request baru.

## Langkah 2 — Hipotesis Akar Masalah
- **H1**: Variabel `activeController` yang sifatnya global/shared diset ke `null` oleh request yang sudah *aborted*. Request berikutnya jadi tidak memiliki referensi controller, sehingga tidak bisa di-abort jika ada request baru lagi.
  - **Eksperimen**: Buat tiruan di Node.js. Lihat urutan log di mana finally request pertama berjalan setelah request kedua dibuat.
  - **Hasil**: Terbukti secara logis dan lewat `bug_004_js_concurrency_test.rb`.

## Langkah 3 — Rancang Perbaikan
- **Berkas**: `public/js/api.js:doFetch`
- **Perbaikan**: Simpan referensi controller spesifik untuk request tersebut di variabel lokal `const currentController = new AbortController(); activeController = currentController;`. Pada blok `finally`, lakukan pengecekan `if (activeController === currentController) { activeController = null; }`.
- **Risiko**: Rendah. Pola ini standar untuk mencegah race condition di shared variable.

## Langkah 4 — Terapkan
- Perbaikan diterapkan. Tes hijau. Berkas dipindah ke `test/regression/decrypt/`.

## Langkah 5 — Verifikasi Mutasi (E4)
- Jika perbaikan di-*revert*, regex test untuk memastikan tidak ada penghapusan sepihak kembali mendeteksi blok `finally { activeController = null; }` yang salah. Tes kembali gagal (RED).

## Langkah 6 — Sapuan Kelas Bug
- **Pola**: Penggunaan global/shared variable yang disetel `null` tanpa identitas kepemilikan di async block.
- **Hasil Sapuan**: Tidak ada pola serupa di script lain (`result_panel.js` memiliki `activeDownloadUrl` namun di-*handle* sinkron dengan UI).

## Langkah 7 — Dokumentasi
- BUG-004 ditandai **DIPERBAIKI**.
