# Laporan Perbaikan BUG-005

## Langkah 1 — Konfirmasi dan Batas Masalah
**Gejala**: Memasukkan teks dengan baris baru `\n` tunggal (LF) di antarmuka web, namun saat didekripsi, jumlah bytenya bertambah karena `\n` berubah secara misterius menjadi `\r\n` (CRLF).
**Tahap**: Serialisasi `FormData` pada API Client (Frontend) lalu ekstraksi form parameter di server (`lib/cipher_workbench/api.rb`).
**Batas**: Hanya terjadi saat klien web menggunakan `FormData` untuk merangkum input teks panjang (`input_type == 'text'`). Spesifikasi Fetch/HTML `multipart/form-data` memang memaksa LF menjadi CRLF, memutasi byte.

## Langkah 2 — Hipotesis Akar Masalah
- **H1**: API Sinatra secara default menerima teks mentah dari form multipart persis seperti yang dikodekan peramban. Oleh karena itu, backend menerima `\r\n` meskipun pengguna menempel `\n`. 
  - **Eksperimen**: Simulasikan form data POST melalui `Rack::Test` dengan menyisipkan `\r\n` untuk memalsukan perilaku browser.
  - **Hasil**: Terbukti secara logis bahwa API menerimanya tanpa dikembalikan ke `\n`. Hal ini wajar bagi form web klasik, tetapi merusak keutuhan dekripsi cipher yang sensitif terhadap spasi/baris baru.

## Langkah 3 — Rancang Perbaikan
- **Berkas**: `lib/cipher_workbench/api.rb`
- **Perbaikan**: Di blok pemrosesan `/api/encrypt` dan `/api/decrypt` ketika `input_type == 'text'`, tambahkan `txt = txt.gsub("\r\n", "\n") if txt` *sebelum* memvalidasi dan mengirimnya ke backend engine.
- **Risiko**: Sangat rendah. Apabila pengguna menempel CRLF asli dari notepad Windows, ia akan terkonversi ke LF (seperti konvensi file Unix dan textarea DOM standar). Ini menyeimbangkan perbuatan diam-diam `FormData`. Untuk integritas byte presisi tinggi, pengguna seharusnya mengunggah File (.dat) di mana `FormData` tidak merusak `tempfile`.

## Langkah 4 — Terapkan
- Perbaikan diterapkan. Tes `test/regression/decrypt/bug_005_crlf_normalization_test.rb` HIJAU.

## Langkah 5 — Verifikasi Mutasi (E4)
- Jika penggantian `gsub("\r\n", "\n")` dibatalkan, asersi tes `assert_equal "A\nB", plain_text` akan langsung gagal karena berisi `\r`.

## Langkah 6 — Sapuan Kelas Bug
- **Pola**: Penggunaan `params[:text]` di aplikasi web Ruby/Sinatra yang diasumsikan presisi bytenya.
- **Hasil Sapuan**: Semua endpoint (`encrypt` dan `decrypt`) yang membaca text sudah diperbaiki.

## Langkah 7 — Dokumentasi
- BUG-005 ditandai **DIPERBAIKI**.
